但 `management.health.elasticsearch.enabled=false`，健康检查不会因为 ES 直接失败。

与 2.1.1 本地基线的关键差异：

- 2.1.1 当前使用 MySQL `device` 库。
- 2.11 默认使用 PostgreSQL `jetlinks` 库，并启用 TimescaleDB。
- 2.11 默认端口仍是 `8848`，需要改成独立端口才能和 2.1.1 同时运行。
- 2.11 默认 `jetlinks.server-id` 由 `spring.application.name:server.port` 组成，改端口后运行时服务 ID 会变化。

下一步启动 2.11 后端前，应先决定：

1. 使用 PostgreSQL/TimescaleDB 作为 2.11 原生基线，还是临时切 MySQL。
2. 如果使用 PostgreSQL/TimescaleDB，需要先创建独立数据库，例如 `jetlinks_211_migration`。
3. 创建 `application-local.yml` 或通过命令行传参，不要直接修改 `application-default.yml`。
